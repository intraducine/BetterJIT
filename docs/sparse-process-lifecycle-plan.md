# Bounded guest process and syscall integration plan

Reviewed source snapshot: `3e8d7ef37e5d0df6efb21691fc530ddc25419601`, experimental/sparse-guest-backing, 2026-10-15. This is a proposed next integration, not implemented fork/exec/clone support. Current B3 creates Process/Thread records in the host harness. No phone data, physical-device action, stock-preloader work or production-mode change is part of this plan.

## Acceptance target and scope

A small static x86-64 ELF must issue real guest fork, execve, clone, wait4 and exit syscalls through generated FEX Wasm. Guest instructions must choose parent/child paths and supply their own high-VA buffers, argv/envp and thread stack/TLS. Only initial boot and worker provisioning belong to the host. A host-created record, host-selected child instruction stream or synthetic syscall producer does not satisfy this gate.

Implement separate reviewed stages. Keep the default runtime fenced from broker1; uncovered syscall, clone flag, instruction or executable-alias cases stop explicitly before effects. The first lifecycle profile uses immutable private RX code, no dynamic interpreter, no multithreaded exec, no vfork/clone3, no signal frames/restart and no persistent step cache. Limit the fixture to at most eight total retained internal contexts, including retired/replaced contexts; do not silently relax the current bound.

## Stage 1: authenticated user-memory boundary

Add a small kernel-only adapter bound to the exact live thread record/lease, process address space and image generation. Methods accept complete u64 BigInt addresses. Convert only validated bounded byte counts or indices to Number. Return copied bytes or typed outcomes, never mutable frame views or a process selector supplied by a guest. `cpu(t)` remains the only selected-handler architectural accessor, after the spilled completion has checked transport ownership.

Proposed operations are copyIn(address,count), copyOut(address,bytes), readU64, readCString and readPointerVector. Start with a 64 KiB per-call transfer cap, 4 KiB pathname cap, 1024 vector entries and 128 KiB total exec argument/environment storage. These are declared profile bounds, not claims to implement every Linux size limit. Specify whether each excess is a Linux errno or a profile UNSUPPORTED result before admission; never truncate pointers or silently truncate strings. NUL scanning must stop at the terminator rather than demand access to the remainder of a maximum-size range. Vectors retain high pointer bits and validate every pointed-to string and total byte count.

Simple copyOut can use the existing whole-range transactional write when no external operation precedes it. Reads into guest buffers require a prepared write transaction: validate every destination page and allocate all required private-view detachments before consuming input. The transaction records address-space/image and mapping generations and owns staged frames. Commit publishes the selected byte prefix without allocation or unchecked lookup; cancel releases staging without changing mappings or bytes. Initially allow no await/reentrant callback or mapping change between prepare, data acquisition and commit. If the operation would block, cancel staging and park only the request; on retry prepare again before consuming input. Later asynchronous mappings require an explicit pin/generation policy, not an unchecked retained span.

Admit write to a bounded captured console and read from a bounded immutable in-memory file first. Copy all write bytes before any output or file-position change. For read, preflight destination, obtain bytes without advancing the description, then commit destination and position in the authority. Add pipe dequeue only after its peek/commit behavior is audited. Define partial-I/O behavior explicitly; do not describe whole-call rollback as general Linux copy_to_user semantics. The Linux user-access API can report copy failure separately; this adapter is a deliberate bounded implementation choice. [Linux user access documentation](https://docs.kernel.org/core-api/mm-api.html#user-space-memory-access)

Required tests: high VA and same-low32 decoys, cross-page i64/string/vector, NUL before inaccessible next page, last-byte boundary faults, read-only destination, PROT_NONE, deterministic COW allocation failure and unchanged file position/pipe queue/output on preflight failure. Two same-mm threads must read/write only their own CPU state and see shared guest bytes; stale lease/image generation and dead-worker completions must have no effect. Run both synthetic protocol tests and actual generated SYSCALL units.

## Stage 2: prepared sparse image and worker lifecycle

Introduce a prepared image object with exclusive ownership of a new GuestAddressSpace, copied executable payloads, translator-space generation, initial stack, architectural state and a reserved internal context/slot. It exposes commit and idempotent cancel. Cancellation closes every staged frame, broker registration, native code space and reservation; no process/fd/child entry is published.

For the first loader accept only ELF64 little-endian x86-64 ET_EXEC fixtures with bounded program-header count, no PT_INTERP and no writable executable mapping. Validate all u64 arithmetic before converting file offsets/sizes to bounded indices: file span, filesz <= memsz, canonical VA interval, alignment/congruence, non-overlap policy, entry in RX and stack separation. Stage RW bytes/zeroed BSS, then final protections, all before publication. Reject unsupported valid ELF layouts explicitly. Build a 16-byte-aligned initial stack using checked writes, full-width argc/argv/envp/auxv pointers, mapped PHDR/ENTRY values and owned AT_RANDOM bytes. Keep CPU/scratch out of guest VMAs. A malformed or over-budget image must leave the old process and translator generation untouched.

Split thread preparation from publication. A newly provisioned worker starts behind a shared-memory start gate. The host reports READY or confirmed failure via shared control state that the synchronous kernel loop can service; a postMessage callback alone cannot wake a blocked kernel loop. The parent syscall may park with an explicit pending-operation kind while readiness is pending. Publish the child only when its context, code and worker are ready, then release its start gate. Worker creation failure before publication unwinds the staged operation. Any late readiness/failure event carries the exact lease/generation and cannot target a reused slot.

The current Node host releases occupancy from the worker exit event (`tests/sdk/linux-host/workers.cjs`). The browser page instead schedules occupancy release 200 ms after disposal (`web/linux_main.js`), while `web/owned_workers.js` has no worker-exit acknowledgement. That timer is not the acknowledgement contract required here. Broker1 is not wired into the default browser worker loader today. Keep browser sparse lifecycle unsupported until a cooperative stop/start-gate acknowledgement or another verified lifetime mechanism exists; Apple Node/Wasm CI does not establish WebKit sparse worker retirement.

## Stage 3: actual fork, wait4 and exit

Initially admit fork only from a single live thread with an allowed signal/disposition state. Reserve the child context/slot and call the storage fork method into a staged child address space. Copy the caller's complete spilled CPUState, lazy flags and rounding state into a distinct internal memory. The child resumes at the admitted post-SYSCALL RIP with RAX=0; the parent receives the published PID. Copy metadata and descriptor-table entries while retaining the same open file descriptions/offsets as required. No child, fd reference or parent-child link becomes observable before successful preparation. On allocation/spawn failure return a documented errno with the parent at its syscall continuation and every staged child reference released.

Add dedicated sparse wait4/exit paths rather than legacy exitThread/exitProcess. Distinguish Linux encoded exit status from profile/transport terminal status. A successful wait copies status before reaping; EFAULT must leave the zombie waitable. Default SIGCHLD, blocked masks and explicit ignored/caught dispositions need a small native oracle and an explicit admitted policy; do not blindly use B3 signal queuing, which intentionally refuses pending signals at the next BEGIN. Keep general delivery unsupported before creation if its disposition could be needed. The parent can park without blocking the authority, and exit wakes its child waiters once. Confirmed worker failure is reported distinctly, never as guest successful exit.

Instruction prerequisite: add a narrowly bounded TEST/CMP and direct Jcc/JMP family with complete FEX IR/effect checks and native flag/branch oracles. Version step/coverage metadata for fallthrough versus finite branch continuation sets; kernel FINISH validates the actual full RIP against that trusted set. Do not retain today's forced fallthrough RIP for branches. Fault/unsupported paths restore full state after unwind. Keep indirect control flow, CALL/RET/stack effects and wider arithmetic unsupported until separately reviewed.

## Stage 4: bounded execve

Admit only a single-threaded process leader initially. Read path/argv/envp from the old image through the checked adapter, then prepare the complete new static image and replacement worker behind a start gate. Failed preparation returns to the old continuation with old descriptors, mappings, code and signal mask unchanged. Keep PID identity, preserve the calling blocked-signal mask, and apply CLOEXEC/caught-disposition rules only at commit.

Define an explicit irreversible commit point after all fallible preparation. Stop the old worker at its spilled boundary and wait for host termination acknowledgement before releasing old memory/code or starting replacement execution. New and old image generations must never share a CPU/scratch registration. Once the old image is irreversibly retired, a later failure is a fatal launch outcome; it cannot pretend to return errno into the old image. Linux likewise distinguishes errors before and after its exec point of no return. [Pinned Linux v6.12 exec implementation](https://raw.githubusercontent.com/torvalds/linux/v6.12/fs/exec.c)

Reject multithreaded exec, nonleader exec, interpreter/shebang/dynamic loading, vfork and execveat until their separate semantics are designed and tested. The existing default adapted Wine exec path is not evidence for this new profile.

## Stage 5: bounded same-mm clone

Add the explicit x86-64 clone argument contract, validate the entire flag combination and refuse unknown bits. Initial thread support requires VM|SIGHAND|THREAD plus the FS/FILES sharing assumptions represented by Process today, exit_signal=0, a nonzero checked guest stack, and only individually implemented SETTLS/PARENT_SETTID/CHILD_SETTID/CHILD_CLEARTID options. Requiring FS/FILES is a profile restriction, not a claim that Linux mandates them. The Linux implementation does require THREAD => SIGHAND => VM. [Pinned fork implementation](https://raw.githubusercontent.com/torvalds/linux/v6.12/kernel/fork.c), [clone UAPI](https://raw.githubusercontent.com/torvalds/linux/v6.12/include/uapi/linux/sched.h)

Reserve the thread context/worker and preflight every TID copyout before any store or publication; commit all accepted TID stores and thread membership together. Set child RAX=0, RSP and FS in its own CPU memory; inherit the specified signal mask. CHILD_CLEARTID writes and wake must use the same guest authority/key rules after guest execution stops, with a precise policy for an invalidated pointer. No direct mm.dv write or worker-local futex shortcut is allowed.

This transactional admission policy must not invent Linux clone fault semantics: the pinned kernel ignores failure of the parent-TID store, and a native x86 oracle confirms that invalid parent/child TID addresses can still yield a successfully created child. Initially reject inaccessible TID destinations as profile UNSUPPORTED before effects, rather than claiming Linux would return EFAULT or roll creation back. Test the accepted mapped-pointer subset against native behavior; later support must model best-effort TID stores and clear-TID failure/wake behavior explicitly. VM without THREAD, SYSVSEM, PARENT, PIDFD, namespace flags, clone3 and vfork remain explicit unsupported cases.

## End-to-end acceptance and failure matrix

The first real guest fixture boots one ELF, forks a child which execs a second image, then that guest forks/execs a grandchild. The guest itself tests fork return values and controls branches. Three live guest-created processes rendezvous through translated futex syscalls while retaining high-VA private sentinels and canonical shared aliases. Verify exact argv/envp/cwd/fd output and exit/wait propagation. A separately admitted same-mm clone uses its own high guest stack/TLS and CPU/scratch, and demonstrates PRIVATE wake plus clear-TID behavior. Keep total retained contexts <=8; record each creation's actual guest syscall RIP and parent PID, not a host-assigned lineage label.

Inject failures at every prepared-image page allocation, internal allocation, slot reservation, code-space upload, worker startup, TID/status copyout and exec preparation stage. Assert unchanged parent/old image and external I/O state where promised, zero unpublished child/fd references, no runnable orphan, preserved shared alias identity and eventual zero backing/queues. Terminate workers before readiness, while parked and during replacement; deliver late timer/readiness replies after slot reuse and prove no mutation. Maintain the long/NULL futex transport regression. Run an independent native x86 oracle for admitted instruction and selected Linux process semantics, then real FEX/Wasm source and exact SDK runs, then Apple CI. No host result substitutes for device or RAM measurements.

Implementation order is Stage1 memory/transaction tests, Stage2 lifecycle staging, branch admission, fork+wait+exit, static exec and finally restricted clone. Keep each source change independently reviewable and export its exact committed SDK. Do not turn on additional syscall numbers merely to get the fixture past a failure. The stock Wine/preloader and full sparse Wine gates remain later work.
